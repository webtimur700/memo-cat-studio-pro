# Выбор LLM-модели: замеры

Дата замеров: 2026-09-24. Машина: Ryzen 7 8845HS (16 потоков), 32 ГиБ ОЗУ общая с iGPU Radeon 780M
(GTT до 15.7 ГиБ), LM Studio (Flatpak) 0.4+ с включённой JIT-загрузкой. Видео: `~/Видео/myvideo.mp4`.
Сырые данные: `docs/llm_benchmark_raw.json` (раунд 1), `docs/llm_benchmark_v2_raw.json` (раунд 2),

## 0. Что на самом деле установлено (расхождение с заданием)

|---|---|---|---|---|---|

## 1. Методика

* **Промпты — рабочие**: `llm/prompts/{titles,description,hashtags}_prompt.py`, три запроса на клип.
* **Входы**: 4 момента по 30 с из видео (окна с 150, 210, 990 и 60 с): три с речью и один без речи (частый случай).
  К каждому прилагается кадр обложки (`docs/llm_benchmark_inputs/`).
* **Раунд 1** — расшифровки Whisper с принудительным `language="ru"`, промпты без защиты от выдумывания.
* **Раунд 2** — расшифровки с автоопределением языка, промпты с защитой (`llm/prompts/common.py`),
  режимы `none` (только текст) и `none_img` (текст + кадр).
  **Почему два раунда:** при разборе качества распознавания выяснилось, что речь в видео **китайская**, а
  `language="ru"` превращал её в фонетическую «русскую» кашу («Жанин, уй-ой-ой, гябра»). Раунд 1 кормил модели
  этой кашей; раунд 2 — реальным текстом. Скорость и память от этого не зависят, качество — зависит, поэтому
  выводы о качестве сделаны по раунду 2, а раунд 1 оставлен как данные о скорости и устойчивости к мусору.
* **Режимы рассуждений** (`reasoning_effort`, поле в `/v1/chat/completions`): `none` — выключены, `low` —
  ограничены, `default` — как настроена модель. Проверено на сервере (Gemma и Qwen): `none` реально даёт 0 токенов
  рассуждений (Gemma: 2.4 с против 40 с на пробный запрос); `enable_thinking=false` (chat_template_kwargs) и `reasoning=off` —
  **не работают** (игнорируются; проверено на Gemma), `/no_think` для Qwen не потребовался: `reasoning_effort=none` у Qwen даёт 0 токенов рассуждений.
* **Время** — на весь клип (3 запроса подряд). Первый клип каждой модели включает «прогрев» (страницы
  весов подгружаются с диска по mmap): Gemma 59 с против 24–27 с на следующих, Qwen3.6 72 с против 28–37 с.
* **Память** — фоновый замер каждые 0.5 с: `MemAvailable` из `/proc/meminfo` и `mem_info_gtt_used`
  iGPU (веса, ушедшие на GPU через Vulkan, занимают GTT, т.е. ту же оперативную память).
* **Контекст** модели при загрузке — 16384 (бенчмарк) / 8192 (приложение) вместо 262144 по умолчанию:
  при JIT-загрузке LM Studio берёт максимальный контекст, а это гигабайты KV-кэша впустую.
* **Оговорки**: часть замеров шла параллельно с моими тестами и сборкой кода (короткие всплески нагрузки на CPU);
  каждый вариант — 1–4 клипа, поэтому времена — ориентир с разбросом, а не точная статистика; оценка качества
  текста — моя, субъективная (один рецензент).

был 11.8 ГиБ (Gemma), 13.2 ГиБ (Qwen3.6) и **16.8 ГиБ (Qwen3.8)**.

| Модель | none | low | default | Вывод |

### 2.5 Качество текста (мои оценки по чтению, раунд 2, 1–5)

| Модель | Русский язык | Цепкость заголовков | Верность видео (без выдумок), только текст | Верность с кадром |
|---|---|---|---|---|
| Gemma 4 26B-A4B | 4 | 3.5 | **4** — при отсутствии речи остаётся общей («Соберите коллекцию милых моментов»), без выдуманных деталей | **4.5** — «щенок с закрытыми глазами», «кот рядом с радиатором» |
| Qwen3.6 35B-A3B | 4 | **4.5** — самые яркие, капс, эмодзи | 2.5 — на клипе без речи в раунде 1 придумал хомяка, панду, пылесос | 2.5 — «лягушка в шоке» (лягушки нет), короткие описания, ломается формат |
| Qwen3.8 27B | 4 | 3 — ровные, «водянистые» | 3 — придумывает «хозяина», «пса» | 3.5 — верно, но додумывает («кот открывает кран») |

Ни у одной модели не было проблем с русским языком; все 3 выдерживают формат «ровно 10 заголовков, ≤ 60 символов»
в режиме `none` (10/10 заголовков во всех клип-прогонах обоих раундов; самый длинный заголовок — 59 символов).
Отдельно: в раунде 1 модели цеплялись за мусор из расшифровки («ЖАНИН, Я К ТЕБЕ ЗАФЛИЮ!»), Qwen3.8 — реже других.

### 2.6 Vision: стоит ли отправлять кадр (пункт 3)

Без кадра и без речи заголовки общие («ОНИ ЭТО СДЕЛАЛИ!», «Досмотри до конца…»), а с кадром — про то, что реально
происходит («Этот щенок слишком серьёзен!», «Кот против радиатора: БИТВА»). Описания перестают быть шаблонными.

| Модель | сек/клип: текст → с кадром | Формат с кадром | Решение |
|---|---|---|---|
| Gemma 4 26B-A4B | 24–27 → 38–39 (+14 с) | 30 хештегов, описание 178–219 симв. — без деградации | **кадр включён** |
| Qwen3.6 35B-A3B | 28–37 (первый 72) → 48–60 | хештегов 14–28 вместо 30, описание 15–227 симв., выдуманные детали | кадр **выключен** (профиль `vision=False`) |
| Qwen3.8 27B | 97–115 → 159–185 (+65 с) | ок, но пик памяти 17 ГиБ | кадр включён (дорого) |

Реализация: `LMStudioProvider.complete(..., images=[jpeg])` (data-URL в `image_url`); в `generate_clip_content`, если модель кадр
не приняла, шаг повторяется в текстовом режиме, а последующие идут без кадра; в JSON рядом с клипом пишется `vision_used`.

## 3. Решение

Рейтинг для автовыбора (`llm/model_selector.py`, `DEFAULT_PROFILES`):

1. **`google/gemma-4-26b-a4b`** — быстрая (≈25 с/клип текстом, ≈38 с с кадром; в пайплайне 107 с/клип вместе со всем остальным),
   формат ровный в обоих режимах, самый низкий пик памяти, с кадром описывает то, что видно. Рассуждения выключены, кадр включён.
2. `qwen/qwen3.6-35b-a3b` — почти так же быстрая и с самыми цепкими заголовками, но тяжелее (20.6 ГиБ, загрузка 105 с), выдумывает детали
   без речи и ломает формат с кадром. Запасной вариант, **без кадра**.
3. `qwen/qwen3.8-27b` — плотная: 100–137 с на клип без кадра, до 227 с в пайплайне, пик памяти 17 ГиБ, качество не выше. Последний резерв.

Правила выбора (см. `docs/llm_benchmark.md` §3 и код): override из `.env` → исключить embedding → лучшая по рейтингу из тех, что помещаются в
`MemAvailable + память выгружаемых LLM − резерв 6 ГиБ`; не поместилась — следующая. Причина решения пишется в лог.
Оценка занимаемой памяти = 0.8 × размер GGUF + 1 ГиБ KV-кэша (по замерам: падение `MemAvailable` при загрузке — 50–66% размера файла,
пик при генерации с кадром — до 80%). На вашей машине в покое (24 ГиБ доступно) выбирается Gemma 4 26B-A4B.

## 4. Воспроизведение

```bash
# входы: python scripts/benchmark_prepare_inputs.py ~/Видео/myvideo.mp4 150 210 990 60   (потом transcript руками/из whisper)
PYTHONPATH=. python scripts/benchmark_llm.py --inputs docs/llm_benchmark_inputs/inputs_v2.json \
    --out docs/llm_benchmark_v2_raw.json --modes none none_img
PYTHONPATH=. python scripts/benchmark_pipeline.py chunk.mp4 --models google/gemma-4-26b-a4b qwen/qwen3.6-35b-a3b
python scripts/benchmark_report.py     # таблицы из сырых JSON
```
Запускать внутри Distrobox (`distrobox enter memo-cat-studio`), LM Studio должна быть запущена на `localhost:1234`.
`lms` из Flatpak-версии LM Studio к демону не подключается, поэтому всё делается через REST (`/api/v1/models`, `/api/v1/models/load|unload`).
