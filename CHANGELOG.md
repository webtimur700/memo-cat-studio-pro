Все версии до первого стабильного релиза документируются по шагам разработки
(не по датам — проект строится непрерывно в рамках одной сессии
проектирования).

## [Unreleased]

### Изменено — LLM, анализ видео, установка (2026-09-26)
- Тексты клипа (10 заголовков, описание, хештеги) — **один запрос** к LM Studio с ответом по JSON-схеме (`response_format: json_schema`)
  вместо трёх: кадр и расшифровка обрабатываются моделью один раз. Gemma 4 26B с кадром: 38.8 → 28.4 с на клип (A/B на 4 входах),
  целое видео 739 → 601 с; откаты на отдельные запросы. Перевод субтитров остаётся отдельным запросом (нужен до кодирования).
  `docs/llm_combined.md`, `scripts/benchmark_llm_combined.py`
- Перевод субтитров идёт вне очереди фоновых текстов (`core/priority_lock.py`): раньше мог ждать все накопившиеся тексты (замер: 104 с)
- HTTP 400/422 от LM Studio — `LLMRequestError` (запрос отвергнут), а не «сервер недоступен»
- Детекция сцен и сканирование окон читают видео **одним проходом** (`video/shared_decode.py`): сцены (86/86) и оценки окон (377/377)
  побитово те же; целое видео без LLM 390 → 343 с. VAAPI-декодирование и уменьшение кадра в ffmpeg замерены и отвергнуты
  (медленнее / другие сцены), `docs/analysis_decoding.md`, `scripts/benchmark_decode.py`
- `scripts/setup.sh`: имя контейнера `MEMO_CAT_CONTAINER` (образ `MEMO_CAT_IMAGE`, домашний каталог `MEMO_CAT_CONTAINER_HOME`), точное
  сравнение имён (`grep -w` принимал `memo-cat-studio-test` за `memo-cat-studio`), флаг `--no-run`; `scripts/run.sh` читает ту же переменную
- Проверена установка с нуля в одноразовом контейнере (клон во временную папку): torch без CUDA (`pip` тянул ~5 ГБ библиотек NVIDIA),
  `ALL_PROXY=socks://` больше не роняет загрузку Whisper (`core/proxy_env.py`)

### Изменено — скорость обработки (≈4× на клип)
- Замеры по стадиям: `core/stage_timer.py`, `scripts/profile_pipeline.py`, таблицы в `docs/performance.md`.
  6-минутный кусок `myvideo.mp4`, 7 клипов: 522.8 с → 133.5 с (74.7 → 19.1 с на клип)
- Экспорт: один проход кодирования вместо двух; оверлеи слоями rawvideo RGBA в рамках элементов с кэшем вместо PNG на каждый
  кадр + qtrle (`effects/overlay_layers.py`): 46.4 → 2.9 с на клип (рендер оверлея 30.7 → 0.6 с)
- Аппаратный H.264 через VAAPI (`export/encoder.py`, настройка «Видеокодер»), fallback на libx264; `scripts/setup.sh` ставит
  `mesa-va-drivers-freeworld`; `-slices 4` обязателен (иначе ошибки декодирования); сравнение — `scripts/benchmark_encoders.py`
- Кадры читаются подряд вместо seek на каждый сэмпл (в 5–13 раз быстрее), декодирование в фоне, YOLO в 4 потока,
  детекция сцен параллельно со сканированием, обложка выбирается при кадрировании (без второго прохода по видео)
- Тексты LLM считаются в фоне, пока кодируются следующие клипы (по одному запросу за раз)
- Исправлено: старый `-r 30` на выходе добавлял два повторных кадра в начале клипа (видео отставало от звука на 66 мс)

### Добавлено — проверка обновлений по кнопке
- Настройки → «Обновления» → «Проверить обновления» (`updater/git_updater.py`, `ui/widgets/update_panel.py`): только по нажатию,
  `git fetch` в фоновом потоке, список новых коммитов; «Обновить» — после подтверждения (кнопка по умолчанию «Нет») и только
  fast-forward (`git merge --ff-only`)
- Не обновляет и объясняет почему: есть незакоммиченные изменения отслеживаемых файлов (перечисляются), ветка разошлась с
  удалённой, нет upstream, нет сети/git; во время обработки очереди обновление отказывается; неотслеживаемые файлы не мешают
  (если коммит перезаписал бы такой файл, git сам откажет)
- Изменились зависимости (pyproject.toml) — сообщается, что нужен `pip install -e .`
- В distrobox без git используется git хоста (`distrobox-host-exec`)
- Проверено на реальных git-репозиториях (сервер + две копии) и на настоящем репозитории проекта
